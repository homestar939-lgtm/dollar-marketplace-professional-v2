# جاهزية الإصدار الرسمي — دولار ماركت بليس

**الحالة:** أساس تجاري قوي موجود، لكن التطبيق ليس جاهزاً بعد لإصدار عام حقيقي. هذا التدقيق مبني على الشيفرة الحالية، لا على نشر إنتاجي أو تجربة ميدانية. لم يُنشر التطبيق ولم تُنشأ خدمة إنتاج في هذه المرحلة.

## ما هو موجود بالفعل

- تسجيل بالبريد وكلمة المرور مع حالة تحقق، وتحقق خادمي من Google ID token.
- صلاحيات API لأدوار المدير والمخزن والمتحصل والمحاسب والمشتري.
- دورة الطلب والتجهيز الجزئي والفاتورة وسند القبض والدفتر والعمولة والتقارير الأسبوعية/الشهرية/السنوية.
- سجل تدقيق وإشعارات داخل التطبيق، ومزامنة SSE لأحداث الطلب والفاتورة والسند.
- تطبيق Android أصلي بـ Jetpack Compose وMaterial 3، مع onboarding ولوحات الأدوار الأساسية.

وجود المسارات والخدمات لا يعني أن كل رحلة مستخدم مكتملة في الواجهة أو أن الخدمة الخارجية متصلة.

## تحسينات أمان الإصدار الجاري تنفيذها

- رفض تشغيل API في الإنتاج مع دخول Demo أو إظهار رموز التحقق/استعادة كلمة المرور أو سر JWT قصير أو CORS عام/غير HTTPS.
- منع شاشة تبديل الأدوار التجريبية في بناء الويب الإنتاجي، وجعل مصادقة Android الحقيقية هي الافتراضية.
- جعل إنشاء بيانات العرض محصوراً ببيئات التطوير، وتوفير إنشاء مدير إنتاج أول مرة فقط عبر أسرار بيئة خاصة، دون حسابات أو منتجات تجريبية.
- إيقاف إنشاء Android release ما لم تُضبط واجهة API الآمنة وGoogle OAuth ومفتاح التوقيع الخاص.

## نواقص تمنع وصفه بأنه إصدار نهائي

1. **التفعيل بالبريد:** API ينشئ رمز التحقق، لكن إرسال البريد غير موصول. من دون مزود بريد حقيقي لن يستطيع العميل إكمال التفعيل أو استعادة الحساب بالطريقة الطبيعية.
2. **Google OAuth الإنتاجي:** يلزم ضبط عميل Google الصحيح في الخادم وAndroid والويب، ثم اختبار تسجيل حقيقي على أجهزة وحسابات إنتاجية.
3. **التسليم:** لا توجد رحلة واجهة مكتملة لتسجيل وقت التسليم وإثباته وعرضه للمشتري. نقطة Android V3 الخاصة بالتسليم غير موصولة بالخادم وفق مراجعة الشيفرة.
4. **المستندات الرسمية:** بيانات توقيع وتذييل الفاتورة والسند موجودة في المخطط، لكن لا يوجد حالياً مسار كامل لمعاينة/تنزيل/طباعة مستند رسمي يحمل هوية الوكالة وتوقيعها.
5. **الحوكمة والصلاحيات:** واجهة المحاسب الحالية تتيح اعتماد/رفض الفواتير والسندات؛ المطلوب الجديد يقول إن المحاسب للعرض فقط إلا بتصريح المدير. يجب اعتماد هذا التغيير صراحةً لأن دوره الحالي جزء من ضوابط الدفتر المالي.
6. **قنوات التنبيه:** الموجود إشعارات داخلية؛ لم يُحدّد أو يُربط إرسال رسمي عبر البريد أو Push أو SMS أو WhatsApp.
7. **الواجهة:** بعض حقول العرض الاختياري للمنتج لا تظهر في واجهة المشتري، كما أن الواجهة الإدارية لا تغطي إعداد نصوص المستندات والصلاحيات بالكامل. في Android توجد عناصر Compose وMaterial 3 أساسية، لكن بعض الطلبات مثل shimmer حقيقي، مبدّل الوضع الفاتح/الداكن، swipe-to-delete وpull-to-refresh غير مكتملة.
8. **التشغيل:** يلزم عنوان API عام عبر HTTPS، قاعدة PostgreSQL إنتاجية، نسخ احتياطي ومراقبة، مفاتيح Google، ومفتاح توقيع Android محفوظ في مخزن أسرار. لم تُجر تجربة تشغيل على أجهزة ميدانية أو رحلة مالية من البداية للنهاية مع مستخدمين حقيقيين.

## قرارات المنتج التي يجب تثبيتها قبل تغيير قواعد المال

- هل يرسل المتحصل السند فيُرحّل المبلغ فوراً، أم لا يخصم من رصيد المشتري إلا بعد اعتماد المحاسب؟ ومن يملك الاعتماد أو الرفض أو التجاوز؟
- هل المحاسب للعرض فقط، أم يملك الاعتماد حالياً، أم يمكن للمدير منح صلاحية مؤقتة له؟
- من يؤكد `تم التسليم`: المخزن/المندوب أم المشتري؟ وما الإثبات المقبول، وهل رقم الهاتف ووقت التسليم إلزاميان؟
- هل السند والفاتورة بعملة الوكالة فقط أم توجد عملات متعددة؟ إذا تعددت، ما سعر الصرف ومصدره وتاريخه؟
- ما القنوات الرسمية المطلوبة للتنبيهات، وما الاسم والعنوان والتوقيع القانوني الذي يظهر لكل وكالة وعلى مستنداتها؟

## متطلبات التهيئة السرية

لا تُرسل كلمات المرور أو مفاتيح التوقيع في المحادثة أو المستودع. توضع في مخزن أسرار بيئة النشر. إنتاج API يحتاج `NODE_ENV=production`، وسر JWT قوي، و`CORS_ORIGINS` من أصول HTTPS محددة، وتعطيل Demo والتوكنات المكشوفة. إنشاء أول مدير إنتاج عملية أحادية المرة، وتُمرّر لها `SEED_ADMIN_NAME` و`SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD` من مخزن الأسرار. إصدار Android يتطلب `API_BASE_URL` و`GOOGLE_WEB_CLIENT_ID` وبيانات مفتاح التوقيع عبر Gradle properties.

## الترتيب المقترح للإكمال

1. إقفال إعدادات الإنتاج والبناء، وربط مزود البريد وGoogle OAuth.
2. الاتفاق على سلطة اعتماد السند والتسليم، ثم تثبيت قواعد العمل والاختبارات المالية.
3. إكمال رحلة التسليم وإشعارات الأطراف والمستندات الرسمية القابلة للعرض والطباعة.
4. إكمال شاشات الإدارة لإعداد الوكالة ونصوص الفاتورة والسند والصلاحيات وسجل الأحداث.
5. تحسين تجربة Android والويب، ثم اختبار قبول متكامل على بيئة staging قبل أي نشر عام.
